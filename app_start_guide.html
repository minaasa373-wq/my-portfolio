before you build / 作る前の見取り図

アプリを作りたい。
で、どのアプリ？ ひとことで「アプリ」と言っても、動く場所も作り方も公開のしかたも別物です。

まずは全体の地図を見て、次に質問へ答えてください。「はい/いいえ」で進むと、あなたが作りたいものに必要な種類・保存のしかた・作り方・公開先が1枚にまとまります。

AXIS A

どこで動くか

＝利用者がどうやって開くか

Webアプリ

BROWSER

ブラウザでURLを開くだけで使えるもの。インストールが要りません。

  • 審査なし、公開まで最短
  • URLを送るだけで共有できる
  • 作るのがいちばん簡単
例：予約フォーム、診断ツール、社内の集計画面

PWA

HOME SCREEN

中身はWebアプリのまま、スマホのホーム画面にアイコンを置けるようにしたもの。

  • ストアの審査も登録料も不要
  • 見た目はスマホアプリそのもの
  • 設定ファイルを1つ足すだけ
例：毎日開く記録アプリ、店舗スタッフ用ツール

スマホアプリ

NATIVE

App StoreやGoogle Playからインストールするタイプ。カメラや通知を本格的に扱えます。

  • 開発者登録が有料（年間費用あり）
  • 公開に審査があり日数がかかる
  • 作る手間はいちばん大きい
例：写真を撮って加工するアプリ、通知が主役のアプリ
迷ったらWebアプリから。ほとんどの「作ってみたい」は、Webアプリで実現できます。スマホアプリにしたくなったら、あとからPWAにすれば十分な場合がほとんどです。
AXIS B

データをどう残すか

＝ここで難しさが決まる

残さない

LEVEL 1

開くたびに真っさらに戻るタイプ。計算・変換・診断など、その場で完結するもの。

必要なもの：HTMLファイル1枚だけ

この端末だけに残す

LEVEL 2

入力した内容がそのスマホ・パソコンの中に保存され、次に開いても残っています。ただし他の端末からは見えません。

必要なもの：ブラウザの保存機能（localStorage）

クラウドに残す

LEVEL 3

データをネット上に保存し、どの端末からでも、複数人でも同じデータを見られます。

必要なもの：FirebaseやSupabaseなどのデータベース
「難しいアプリ」と「簡単なアプリ」を分けているのは、見た目ではなくここです。データを何人で共有するかを決めた瞬間に、必要な技術が決まります。
AXIS C

どうやって作るか

＝3つのルートがある

AIに作ってもらう

ROUTE 1

ClaudeやGeminiに「こういうものが欲しい」と伝えて、HTMLファイルを書いてもらう方法。

  • いちばん速い
  • 直したい所を言えば直せる
  • 小〜中規模まで対応できる

ノーコードで組む

ROUTE 2

GlideやAppSheetなど、部品を並べて作るサービスを使う方法。データベースやログインが最初から用意されています。

  • 複数人で使うものに強い
  • 月額費用がかかることが多い
  • そのサービスの外には持ち出せない

自分でコードを書く

ROUTE 3

HTML・CSS・JavaScriptを学んで書く方法。時間はかかりますが、思った通りに作れます。

  • 作れるものに制限がない
  • 費用がほぼかからない
  • AIと併用するのが今の主流
AXIS D

Webに公開するまで

＝ファイルを置く場所を借りる

手元で開いて確認する

作ったHTMLファイルをダブルクリックすれば、自分のパソコンでそのまま動きます。ここまでは公開ではありません。

置き場所を用意する

GitHub PagesかNetlifyが定番です。どちらも無料で、ファイルをアップロード（またはドラッグ&ドロップ）するだけでURLが発行されます。

URLを配る

発行されたURLを送れば、相手はブラウザで開くだけで使えます。QRコードにすると配りやすくなります。

必要なら独自ドメインにする

覚えやすいアドレスにしたい場合だけ。年間1000円台から取得でき、あとから設定できます。急ぐ必要はありません。

注意：公開したページは誰でも開けます。名簿や顧客情報などをそのままファイルに書き込んで公開しないでください。人に見せたくないデータを扱うなら、ログインの仕組みが必要になります。
